# 高效 Meeting

> **AUFE课题组科研入门** · 对应论文章节：**Introduction**  
> 来源：手册第六篇 · 模板：[`meeting_template.md`](https://github.com/enco1128/AUFE-Research-group-study-materials/blob/main/resources/01-mindset/meeting_template.md)

## 本页目标

- 把 Meeting 当成「暴露问题、澄清思路、获得反馈」，而不是进度表演  
- 会用六段模版准备每一次讨论  
- 遵守实验室讨论原则  

## 为什么要 Meeting

1. 目的是**更高效推进科研**，探索与暂时没有进展都很正常，不要把 Meeting 只当成压力场  
2. 核心不是「证明自己做了很多」，而是**暴露问题、澄清思路、获得反馈、推进下一步**  
3. 除定期 Meeting 外，有需要随时约；**培养有问题就讨论的习惯**  

## 组织形式与频率

**已有 Project**

- 以 Project 为单位开会；Project leader 协调时间  
- 每个 Project 维护一份短文档：目标、Technical Contribution、时间规划、成员分工、进展、结果与问题（**凝练，不长篇**）  
- 至少 **2 周**一次；有重要结果可随时约  

**个人学习阶段（尚未进 Project）**

- 维护个人进展文档：关注点、近期论文（一句话摘要）、思考与待讨论点  
- 博/硕士建议至少 **2 周**一次；校外实习 / 本科实习至少 **1 月**一次  

## Meeting 六段模版

1. **Review** 大方向与 Contribution：自己是否还在正确路上  
2. **回顾** 上次结论与 Todo  
3. **进展** 三句话以内讲清  
4. **讨论清单**：问题、有意思的现象、观察  
5. **文献分享**：最近读的几篇 + 各一句话总结  
6. **后续 Todo** 与时间安排  

可复制：[`resources/01-mindset/meeting_template.md`](https://github.com/enco1128/AUFE-Research-group-study-materials/blob/main/resources/01-mindset/meeting_template.md)

## 实验室讨论原则

1. **充分交流**：有问题及时问；目的是正确、高效地解决疑问  
2. **平等交流**：不是单向汇报；有想法请表达；不同意请礼貌质疑——不要表面服从、底下另搞一套  
3. **高效真诚**：直入主题  
4. **事事有回应**：讨论出的 Todo 必须闭环  

## 正面 vs 负面模式（摘要）

| 高效模式 | 低效模式 |
|----------|----------|
| 遇失败会分析原因（方法/数据/实现/假设） | 只报「效果不好」，无归因 |
| 「有结果 → 碰问题 → 已试方案 → 下一步」结构清晰 | 每周只汇报，无讨论与规划 |
| 能快速试错与验证 | 拖沓试错，跟进弱 |
| 对新概念有好奇心，会补读再讨论 | 卡住后缺少主动推进 |

## Checklist

- [ ] 用六段模版写好下一次 Meeting 提纲  
- [ ] Project / 个人进展文档已更新且足够短  
- [ ] 上次 Todo 全部有回应状态
