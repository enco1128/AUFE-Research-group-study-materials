> 来源：手册第十六篇 · 句式：[`rebuttal_templates.md`](https://github.com/enco1128/AUFE-Research-group-study-materials/blob/main/resources/05-writing/rebuttal_templates.md)  
> 外部参考：[MLNLP Paper-Rebuttal-Tips](https://github.com/MLNLP-World/Paper-Rebuttal-Tips)

## 本页目标

- 理解 Rebuttal 是「统筹一盘棋」，不是逐条发泄  
- 对常见质疑有回应策略  
- 会写简洁、可核对的回复句式  

## 原则

1. **有问必答，不漏点**：篇幅紧可合并同类意见，不可擅自删点  
2. **揣摩审稿人倾向**：明确「若解决 xxx 可提分」的意见优先争取；用正面意见巩固盟友；对负面意见分配主要篇幅澄清  
3. **全局统筹**：篇幅资源按「影响录用的关键度」分配  
4. **能缩写则缩写**，把空间留给硬问题  
5. **发现 factual error**：礼貌指出，并可在 AC Message 中提示，降低错误意见权重  

## 常见问题类型

| 类型 | 回应思路 |
|------|----------|
| Novelty 不足 | 澄清相对已有工作的**具体差异**与问题设定；引用审稿人已认可的优点交叉印证 |
| Factual error | 先纠正事实，再给证据（引用、公式、实验设置） |
| 提升有限 | 说明指标含义、难度设定、与 SOTA 差距来源；补充分析/消融证明「有效且为何有效」 |
| 实验不充分 | 能补则补关键实验；不能补则说明局限与计划，并给出已有证据边界 |
| 语法/结构/漏引 | 致谢并列出已修改位置；逐条补齐 |

## AC Message

用极短篇幅向 AC 概括：主要争议点、你已解决/澄清什么、为何仍值得接收。避免情绪化；强调证据与共识。

## Checklist

- [ ] 每位审稿人意见均有对应段落（或合并说明）  
- [ ] 新增实验/图表在正文或附录可定位  
- [ ] AC Message ≤ 篇幅限制且无攻击性表述
